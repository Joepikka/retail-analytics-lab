Key figures

01 · Check the data first

Purchase tracking broke for most of four days

Views kept arriving while purchases stopped being logged. Left in, the gap made weekends look 53% better than weekdays. Taken out, there is no real difference.

Daily revenue

Daily total and 7-day rolling average.

Daily revenue7-day average

How it was caught

An hourly check now flags any hour with real traffic (over 10k events) and zero purchases. Those days are excluded from every conversion figure on this page.

Cart events were also under-logged before mid-October, so the funnel uses view → purchase.

06 · How it was built

Reproducible from raw files to every number

Every step can be rerun. The data tests stop the pipeline if rows or revenue fail to reconcile between stages.

1

Download

4.6 GB gzip over 12 parallel, resumable connections.

2

Ingest

Typed Parquet, plus a SHA-256 manifest so reruns skip unchanged files.

3

Model

DuckDB star schema: event and session facts, product, user and date dimensions.

4

Test

14 checks that reconcile rows and $505M of revenue to the cent.

5

Analyse

SQL marts, a forecast against baselines, and an A/B test design.

6

Report

This site, an Excel workbook, CSVs for Power BI, and a memo.

14 / 14 data tests passing

Row counts, revenue reconciliation, key integrity and value ranges, checked on every run.
